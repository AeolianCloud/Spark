## Purpose

支持 PVE 节点使用非默认 API 端口:登记节点时 host 可携带 `:port` 后缀,系统解析并持久化端口,此后所有对该节点的 PVE API 调用与可达性探测均连接该端口。

## ADDED Requirements

### Requirement: 节点自定义端口登记

系统 SHALL 在登记/更新节点时,从 host 中解析可选的 `:port` 后缀:存在合法的数字端口(1-65535)时持久化为节点端口;未携带端口时使用默认端口 8006。host 中的端口后缀 SHALL NOT 被静默丢弃,且 SHALL NOT 导致 base URL 出现重复端口。

#### Scenario: host 携带非默认端口

- **WHEN** 管理员登记节点时提交 host 为 `117.177.33.8:8007`
- **THEN** 系统持久化该节点端口为 8007,并返回该端口

#### Scenario: host 未携带端口

- **WHEN** 管理员登记节点时提交 host 为 `117.177.33.8`(无端口后缀)
- **THEN** 系统使用默认端口 8006,并返回默认端口

#### Scenario: 非法端口后缀

- **WHEN** 管理员登记节点时提交 host 为 `117.177.33.8:99999` 或 `117.177.33.8:abc`
- **THEN** 系统拒绝该请求并返回参数错误,不登记节点

### Requirement: 节点 API 调用使用登记端口

系统 SHALL 使用节点登记的端口构建所有 PVE API 客户端连接:包括 VM 生命周期操作、VM 状态与列表查询、镜像查询以及节点可达性探测。未登记端口时回退到默认端口 8006。

#### Scenario: 自定义端口节点的状态查询

- **WHEN** 系统对端口为 8007 的节点查询 VM 状态
- **THEN** 系统连接 `https://<host>:8007/api2/json` 发起查询,而非默认 8006 端口

#### Scenario: 自定义端口节点的可达性探测

- **WHEN** 系统对端口为 8007 的节点执行可达性探测
- **THEN** 探测请求发送到该节点 8007 端口

#### Scenario: 默认端口节点的兼容行为

- **WHEN** 系统连接未登记自定义端口的既有节点(host 无端口后缀)
- **THEN** 行为与修改前一致,连接默认端口 8006
